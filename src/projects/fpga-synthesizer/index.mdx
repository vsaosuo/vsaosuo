## Overview

The core challenge of implementing audio synthesis on an FPGA is producing waveforms with low harmonic distortion while keeping resource utilization reasonable. This synthesizer uses Direct Digital Synthesis (DDS) — a numerically-controlled oscillator that accumulates a phase increment each clock cycle and maps the result through a pre-computed sine lookup table stored in block RAM.

## Architecture

Each of the 8 voices runs its own DDS engine with an independent phase accumulator and frequency word. The 100 MHz system clock gives enough headroom to process all voices in a single 48 kHz audio sample period, with cycles left over for the MIDI parser and envelope generators.

The MIDI interface is a 31250-baud UART implemented in VHDL. Note-on and note-off messages are decoded and dispatched to a voice allocator that manages the 8-voice pool using a least-recently-used eviction policy. Each voice has an ADSR envelope generator driven by a lookup table with configurable attack, decay, sustain, and release parameters set through a simple register interface.

## Audio Output

Audio is sent to an external I2S DAC (a PCM5102A) over a 3-wire SPI-style interface. The FPGA acts as the I2S master, generating the bit clock (BCLK) and word select (LRCLK) signals and serializing 24-bit samples at 48 kHz stereo.

## What I Learned

The most interesting debugging experience was tracking down a subtle phasing artifact that appeared only when multiple voices played the same frequency. The root cause was a shared sine table with a read address collision during simultaneous lookups — fixed by duplicating the table into separate block RAM primitives so each voice has its own read port.

FPGA debugging is fundamentally different from software: there's no debugger you can attach, so the workflow is simulating edge cases in a testbench before they ever hit silicon. Writing thorough VHDL testbenches for the DDS core and MIDI parser caught three bugs that would have been extremely painful to diagnose on hardware.
